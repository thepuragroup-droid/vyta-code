HOW THE SYSTEM CHECKS

System checks.
Dated code records.

Learn how the VYTA Code system checks submitted cart records, identifies applied codes and preserves the recorded date, time and result.

01 / READ

Check the record

The system reviews submitted cart, checkout-summary or code-settings records. It identifies the exact code and the information available in the record.

A code appearing in promotional text alone is not treated as an applied result.

02 / CHECK

Match the result

The system checks whether the code appears in the applied-code area and whether the displayed summary supports that result. Incomplete, unreadable or conflicting records are marked for review.

Settings information is distinguished from a code shown applied in a cart.

03 / UPDATE

Keep the history

The system records the supported status with its capture date and time. New observations update the record while earlier observations remain in its history.

Only the review summary is displayed publicly. Supporting records stay private.

Every check keeps its original context

A result describes the submitted cart record at its recorded time. It does not guarantee the same outcome for a later cart.

Capture time
The date and time supplied with the source record. An unconfirmed timezone stays unconfirmed.
Upload time
When the record entered storage. It is kept separate from capture time.
Review time
When the system checked the evidence. Reviewing an older record does not change when it was captured.

One record across the site

The lookup, code pages and archive use the same recorded observations. Rebuilding a page does not create a new code check or refresh an evidence date.
